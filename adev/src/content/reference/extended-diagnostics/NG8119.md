# Platform Check In Control Flow

This diagnostic detects usage of `isPlatformBrowser()` or `isPlatformServer()` from `@angular/common` inside the condition of a control flow block (`@if`, `@switch`, `@for`). It also flags template references to a class field that is initialized from one of these checks (regardless of how the platform id was obtained, `inject(PLATFORM_ID)` or constructor-based DI).

```angular-ts
import {Component, inject, PLATFORM_ID} from '@angular/core';
import {isPlatformBrowser} from '@angular/common';

@Component({
  template: `
    @if (isBrowser) {
      <interactive-widget />
    } @else {
      <static-fallback />
    }
  `,
})
class Dashboard {
  isBrowser = isPlatformBrowser(inject(PLATFORM_ID));
}
```

## What's wrong with that?

While this pattern hydrates correctly, it produces a poor user experience when used together with hydration: the server renders one branch of the control flow and the browser receives that rendered HTML, but once the application bootstraps and hydration completes, Angular re-evaluates the condition on the client and replaces the server-rendered branch with the client branch. Users see a brief flash of the server content before it is swapped for the client content.

## What should I do instead?

Avoid branching on the platform inside templates. Instead:

- Render the same markup on the server and client, and apply platform-specific behavior after hydration completes (for example with `afterNextRender`).
- Use [CSS-only responsive techniques](https://developer.mozilla.org/en-US/docs/Web/CSS/Media_Queries) to handle layout differences between environments instead of swapping templates.
- Move platform-specific decisions out of the template into a service or directive that produces consistent server and client output.

## Configuration requirements

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) must be enabled for any extended diagnostic to emit.
`platformCheckInControlFlow` has no additional requirements beyond `strictTemplates`.

## What if I can't avoid this?

This diagnostic can be disabled by editing the project's `tsconfig.json` file:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "platformCheckInControlFlow": "suppress"
      }
    }
  }
}
```

See [extended diagnostic configuration](extended-diagnostics#configuration) for more info.
